# 08 - Android 开发路线图（分阶段）

## 1. 总体目标

在不改后端契约的前提下，构建可上线的 Android 客户端，分阶段交付。

## 2. 阶段划分

## Phase 0 - Bootstrapping（2-4 天）

目标：项目可编译、可请求线上 API、可展示基本页面。

交付：

- Kotlin + Compose + Hilt + Retrofit 基础框架。
- 网络层 + envelope 解析。
- 健康检查接口打通。
- 基础导航框架。

DoD：

- debug 包可安装。
- 首页能显示“接口可达/不可达”状态。

## Phase 1 - Public Browse + Play（1-2 周）

目标：打通“发现 -> 列表 -> 播放”闭环。

交付：

- 公共曲目列表/详情。
- 随机曲目、热门曲目模块。
- ExoPlayer 播放（播放/暂停/拖动/切歌）。
- 播放模式（4种）与基础队列。
- 播放上报 `POST /public/tracks/:id/play`。

DoD：

- 连续播放 30 分钟稳定。
- 播放失败不崩溃，有友好提示。

## Phase 2 - Auth + Personalization（1 周）

目标：可选登录与鉴权能力。

交付：

- 登录、会话恢复、退出。
- 401 全局处理。
- 管理入口按 `is_admin` 控制显示（仅预留，不必实现全管理功能）。

DoD：

- token 过期后可自动回到匿名态。
- 认证态请求与匿名态请求行为可区分。

## Phase 3 - UX Hardening（1-2 周）

目标：提升可用性和体验。

交付：

- 背景播放通知、耳机控制。
- 图片缓存优化。
- 错误态/空态统一。
- 基础埋点与日志。

DoD：

- 弱网/断网下不崩溃。
- 前后台切换播放状态正确。

## Phase 4 - Optional Enhancements（后续）

可选功能：

- 下载离线
- 歌词增强
- 均衡器
- 多语言

## 3. 里程碑与验收

### Milestone M1（Phase 1 完成）

- 核心播放闭环可演示。
- 能通过如下脚本化回归：
  1. 打开 app -> 加载列表。
  2. 点击曲目 -> 播放。
  3. 切歌 -> 上报。
  4. 切后台 -> 回前台继续。

### Milestone M2（Phase 2 完成）

- 登录和会话恢复稳定。
- 401/403 行为符合预期。

## 4. 建议任务拆分粒度

每个 AI 任务控制在 1~3 天，示例：

1. 网络层与统一错误映射。
2. 列表接口 + 分页 UI。
3. Player 引擎接入。
4. 播放模式状态机。
5. 上报模块。
6. 登录模块。

## 5. 风险前置

1. 后端字段波动 -> DTO 容错策略。
2. 播放器状态复杂 -> 先做状态图再编码。
3. AI 大改风险 -> 小步提交、每步可运行。

## 6. 每周例行检查项

- 契约一致性（是否仍遵循 `success/data/error`）。
- 崩溃率（debug 阶段通过日志估算）。
- 网络失败恢复能力。
- 播放连续稳定性。

## 7. 版本建议

- `0.1.0-alpha`：Phase 1
- `0.2.0-beta`：Phase 2 + 部分 Phase 3
- `1.0.0`：核心稳定 + 基础运营能力
