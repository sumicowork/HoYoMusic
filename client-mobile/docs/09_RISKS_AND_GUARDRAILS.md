# 09 - 风险与护栏（给 AI 的硬性约束）

## 1. 高优先级风险

### R1 - 契约误判

表现：AI 擅自新增字段、修改请求路径、改变响应解析。

约束：

- 接口先看 `docs.json` 或后端源码。
- 不存在的字段必须标注“可选且未使用”。

### R2 - 鉴权混用

表现：把 admin 路由当 public 调用，或 stream token 处理错误。

约束：

- 先用 `public` 路由实现 MVP。
- admin 功能单独开模块，不混在公共列表流程。

### R3 - 播放状态机混乱

表现：切歌、结束、暂停、后台恢复逻辑互相覆盖。

约束：

- 先写状态图与转换表。
- 播放模式逻辑写单元测试后再接 UI。

### R4 - 失败处理缺失

表现：网络超时/404/503 导致崩溃或空白。

约束：

- 所有仓储接口返回 `Result` 或 `Either`。
- UI 统一处理 `Loading/Content/Empty/Error`。

### R5 - AI 大范围重构

表现：一次提交改动过大，难以定位问题。

约束：

- 单次任务 1~3 天工作量。
- 每次提交必须“可编译 + 可运行 + 有验证步骤”。

## 2. 禁止事项

1. 禁止修改 `backend/` API 契约（除非人类明确授权）。
2. 禁止把 token 明文写入普通 SharedPreferences。
3. 禁止在主线程做网络或重 IO。
4. 禁止在异常分支吞错不记录。
5. 禁止对远程 URL 做危险拼接或信任任意输入。

## 3. 代码生成质量门槛

每个任务完成后，AI 必须给出：

1. 改动文件列表。
2. 影响的接口列表。
3. 风险点与回滚方案。
4. 手工验证步骤（最少 3 条）。

## 4. 自检清单（提交前）

- [ ] 项目可编译。
- [ ] 核心路径可运行。
- [ ] 无硬编码本地地址（release 配置）。
- [ ] 错误提示对用户可理解。
- [ ] 无明显内存泄漏点（播放器、协程、监听器释放）。

## 5. 播放器专项护栏

- Player 生命周期与页面生命周期解耦。
- 避免重复创建 ExoPlayer 实例。
- 切换 media item 前后确保状态同步。
- 上报逻辑节流，避免高频刷接口。

## 6. 网络层专项护栏

- Timeout 统一配置。
- Retry 仅用于幂等 GET，且次数有限。
- 429/503 采用退避，不做无限重试。

## 7. 契约变更流程（若必须）

1. 提出变更动机。
2. 列出影响端（Web/Backend/Desktop/Mobile）。
3. 给出兼容方案。
4. 通过后再改。

## 8. 版本回归最小集

1. 列表加载
2. 播放/暂停
3. 切歌
4. 上报
5. 登录/退出（如已接入）
6. 断网重试

## 9. 线上问题应急策略

- 发现严重崩溃：快速回滚到上一个 tag。
- 接口突变：通过远程开关禁用受影响功能入口。
- 数据异常：保留原始响应日志（脱敏后）。
