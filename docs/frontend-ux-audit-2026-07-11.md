# HoYoMusic 前端 UI/UX 精细审计报告

> 日期：2026-07-11 · 范围：frontend 全部页面（公开 + 个人 + 后台 + 系统态）· 方式：只读源码审计，未修改任何文件
> 验证基线：路由树 `src/App.tsx`、桌面导航 `PageHeader.tsx`、移动导航 `MobileTabBar.tsx`、死代码 `SideNav.tsx`、后台布局 `AdminLayout.tsx`、游戏页 `GameDetail.tsx`、专辑页 `AlbumDetail.tsx` 均一手阅读。

---

## 0. 一句话结论

前端**单页质量总体不错**（尤其是 AlbumDetail / TrackDetail 的沉浸式表达、Search 的高级筛选），但**信息架构（IA）层面系统性混乱**：游戏 / 曲库 / 歌曲 / 标签被当成四个平行顶层概念，跳转不对称、存在孤儿页与死链、三套导航互相打架、移动端缺入口。问题集中在"分级与跳转"，而非单页视觉。

---

## 1. 页面层级总图

```
顶级入口（无父列表）
├─ /                        首页（发现/推荐聚合）
├─ /library                 曲库（曲目总表）         ← nav「曲库」
├─ /albums                  专辑（专辑网格）         ← nav「专辑」
├─ /artists                 艺术家（卡片网格）       ← nav「创作者」
├─ /tags                    标签（分组折叠树）       ← nav「标签」
├─ /search                  搜索（工具页）
└─ /me                      我的（个人中心，登录）

二级详情（应挂父列表之下）
├─ /albums/:id              专辑详情   ✅ 父=/albums 存在
├─ /artists/:id             艺术家详情 ✅ 父=/artists 存在（id=编码姓名）
├─ /tags/:id                标签详情   ✅ 父=/tags 存在
├─ /track/:id               歌曲详情   ⚠ 孤儿：无 /tracks 列表父路由
└─ /games/:id               游戏详情   ⚠ 孤儿：无 /games 列表父路由（仅首页卡可进）

后台（独立子系统，requireAdmin）
└─ /admin, /admin/albums, /admin/tags, /admin/games,
   /admin/artists, /admin/users, /admin/analytics,
   /admin/settings, /admin/music-sources/library

系统态
└─ /maintenance             维护页（强制拦截）
```

**层级病灶**：`/track/:id` 与 `/games/:id` 是孤儿详情——内容核心（歌曲）和一级分类（游戏）都没有自己的列表入口，只能从别处"钻"进去，且无法从详情页"回到同类列表"。

## 2. 导航三套不一致（核心病灶）

| 入口 | 文件 | 可见项 | 问题 |
|---|---|---|---|
| 桌面顶栏 | `PageHeader.tsx:83` | 主页/搜索/曲库/专辑/**创作者**/标签 + 消息/登录·我的/管理 | 标签称「创作者」非「艺术家」 |
| 移动底栏 | `MobileTabBar.tsx:31` | 主页/搜索/曲库/专辑/**创作者**/反馈 | **缺「标签」「我的」**；登录态无「我的」入口 |
| 死代码 | `SideNav.tsx` | 主页/搜索/曲库/专辑/艺术家/标签/我的/管理/主题 | **全仓仅自身引用**，从未渲染 |

- **文案混乱**：同一概念三套叫法——桌面+移动叫「创作者」，`SideNav`（死）叫「艺术家」，数据库/接口维度叫 `artists`。用户心智里这是「艺术家」。
- **移动端断裂**：手机用户底部无法到达「标签」页和「我的」页（登录后无个人中心入口），严重可用性缺陷。
- **SideNav 死代码**：含完整导航+主题切换，但 `App.tsx` 用的是 `PageHeader`+`MobileTabBar`，`SideNav` 从未被 import → 应删除，避免后续维护者误以为是"另一套导航"。

## 3. 逐页档案

### 3.1 公开页

**`/` 首页** · `Home.tsx` · 顶级入口
- 看到：游戏卡片网格、随机专辑轮播、随机歌曲跑马灯、热门 Top10、随机播放弹窗（按全部/游戏/艺术家）。
- 操作：点游戏卡→`/games/:id`；点专辑→`/albums/:id`；点歌曲→`/track/:id` 或试听；触发随机播放。
- 合理性：**基本合理但信息架构略杂**。5 区块并列缺乏统一主题，与 `/library`、`/search` 职能重叠，易让用户困惑"去哪都一样"。建议收敛为单一核心（发现/推荐）。

**`/library` 曲库** · `PublicLibrary.tsx` · 一级列表
- 看到：顶部搜索框、曲目表格（封面/标题→`/track/:id`/专辑→`/albums/:id`/时长/操作：播放·下载·收藏·加歌单）、移动端 List 降级。
- 操作：搜索、逐行播放/下载/收藏/加歌单。
- 合理性：**全站最稳健页面**。唯一问题：未登录用户「收藏/歌单」按钮直接**消失**而非置灰+登录引导，造成"按钮哪去了"的困惑。

**`/albums` 专辑** · `Albums.tsx` · 一级列表
- 看到：专辑卡片网格（标题/曲目数/总时长/发行年）、顶部搜索。
- 合理性：**合理且一致**。缺「按游戏筛选」侧栏（专辑多归属游戏，是潜在信息缺口）。

**`/albums/:id` 专辑详情** · `AlbumDetail.tsx` · 二级详情
- 看到：沉浸式渐变 Hero（取封面主色，含封面/中英文名/曲目数·总时长·发行日/FLAC·规格徽章/备注/「播放全部」「下载专辑」）、按碟分组的曲目列表。
- 操作：播放全部、下载专辑、逐曲播放/下载、点曲名→`/track/:id`。
- 合理性：**设计优秀**（沉浸表达契合音乐站）。**致命小问题**：曲目行 `MoreOutlined` 按钮（`AlbumDetail.tsx:179-184`）**无 onClick，死控件**——点无任何反应。应补「收藏/加歌单/分享」菜单或移除。

**`/artists` 艺术家** · `Artists.tsx` · 一级列表
- 看到：艺术家卡片网格（姓名/曲目数/专辑数/角色）、搜索；点→`/artists/${encodeURIComponent(name)}`。
- 合理性：**合理**。注意 id 是「编码姓名」非数字 id，接口/路由约定需固化，避免与 `:id` 数字语义混淆。

**`/artists/:id` 艺术家详情** · `ArtistDetail.tsx` · 二级详情
- 看到：Hero（头像/别名/统计/关联游戏→`/games/:id`）、Tabs（①歌曲表含「角色列」+标题→`/track/:id`+专辑→`/albums/:id` ②专辑网格）。
- 合理性：**合理且是亮点**——「角色」维度（作曲/编曲/演唱）显式呈现，契合 HoYoVerse 多人协作参考站定位。建议 Hero 增加「按游戏拆分作品」二级导航（跨游戏艺术家作品会混杂）。

**`/tags` 标签** · `Tags.tsx` · 一级列表
- 看到：按标签组分组的 Collapse 递归树，点标签→`/tags/:id`。
- 合理性：**合理（桌面）**。**移动端无入口**（见 §2），手机用户到不了标签页。

**`/tags/:id` 标签详情** · `TagDetail.tsx` · 二级详情
- 看到：标签路径面包屑、「播放全部」、曲目表（标题→`/track/:id`、artist_name→`/artists/:name`、专辑→`/albums/:id`）。
- 合理性：**合理且一致**。面包屑对层级标签（游戏/原神/主题曲）表达清晰，是好的信息设计。

**`/games/:id` 游戏详情** · `GameDetail.tsx` · 二级详情（孤儿）
- 看到：**仅专辑网格**（→`/albums/:id`）；`getGameClass()` 硬编码已知游戏 CSS 类（原神/星铁/绝区零/崩坏3/未定/因缘/星布谷地），非硬编码游戏返回空样式。
- 跳入：仅首页游戏卡。
- 合理性：**明显短板，最该改**。
  1. **无 Hero**：不展示游戏名/简介/封面，用户进入后不知看的是哪款游戏，仅靠背景色识别；新游戏（非硬编码 class）**无样式**。
  2. **无「该游戏歌曲」直览**：只能经专辑中转，缺「游戏原声全集」。
  3. **英文 fallback**：未找到态写 `Back to Home` / `Game not found`（`GameDetail.tsx:78-80`），与全站中文不符。
  4. **无父列表 `/games`**：游戏只能从首页进入，导航断裂。

**`/track/:id` 歌曲详情** · `TrackDetail.tsx` · 二级详情（孤儿但内容最丰富）
- 看到：沉浸式 Hero（封面/中英文名/专辑链接/规格卡 FLAC·时长·大小/标签/备注）、操作（播放·下载·收藏·加歌单）、`LyricsDisplay`（点歌词 seek）、`CreditsDisplay`（创作名单）、`MusicSourcesDisplay`（音源）。
- 合理性：**全站信息密度与沉浸感最佳页**。小建议：规格卡（FLAC/大小）对普通用户意义有限，可折叠或仅对登录/下载用户显示。

**`/search` 搜索** · `Search.tsx` · 工具页
- 看到：搜索表单、高级筛选 Drawer（游戏/艺术家/年份/时长/标签）、快捷标签、结果表（高亮+备注片段）、从 `?q=` 恢复查询。
- 合理性：**合理且功能完整**，高级筛选是重设计参考样板。潜在：931 行单文件偏重，结果行默认显备注可能信息过载，建议默认只显核心字段、备注 hover/展开。

### 3.2 个人中心

**`/me` 我的** · `Profile.tsx` · 顶级（登录）
- 看到：Hero（用户名/退出→`/`）、统计（收藏数/歌单数）、「我的喜爱」列表（→`/track/:id`）、「我的歌单」列表（→`/playlists/:id`，创建弹窗）。
- 合理性：**合理**。**移动端无入口**（见 §2）。

**`/playlists/:id` 歌单详情** · `PlaylistDetail.tsx` · 二级详情（父 `/me`）
- 看到：返回`/me`、曲目表（Popconfirm 移除）、「播放全部」。
- 合理性：**合理但偏简陋**。无名称/描述/封面编辑、无分享/排序、空歌单无引导文案。

### 3.3 系统态

**`/maintenance` 维护页** · `Maintenance.tsx` · 强制
- 看到：配置提示、「管理入口」(`openLogin('/admin')`)、「反馈」。
- 合理性：**合理**。默认英文 fallback 与中文 UI 不一致（次要），建议汉化。

### 3.4 后台 `/admin/*`（9 页）

功能完善、数据密度高，符合管理后台预期。子页：曲目管理(`Admin`)、专辑(`AlbumManagement`)、标签(`TagManagement`)、游戏(`GameManagement`)、艺术家(`ArtistManagement`)、用户(`UserManagement`)、统计(`Analytics`)、设置(`Settings`)、音源库(`MusicSourceLibraryManagement`)。
- **致命导航 bug**：`AdminLayout.tsx:37` 退出登录 `navigate('/admin/login')`——该路由不存在，落入 `*`→`/`，用户点退出被弹回首页而非登录页。应改 `navigate('/')` 或 `openLogin()`（`Maintenance` 用 modal 登录印证无独立登录路由）。
- `Analytics`/`AlbumManagement` 文件体积过大（>50KB），重设计时关注拆分与首屏性能。

## 4. 跳转逻辑全局

| 从 → 到 | 状态 |
|---|---|
| 首页 → 游戏/专辑/歌曲 | ✅ |
| 曲库 → 歌曲/专辑 | ✅ |
| 专辑 → 歌曲 | ✅ |
| 艺术家 → 歌曲/专辑/游戏 | ✅ |
| 标签 → 歌曲/艺术家/专辑 | ✅ |
| 歌曲 → 专辑 | ✅ |
| 歌曲 → 艺术家 | ⚠ 仅 credits 内名字可点，无独立字段链接 |
| 歌曲 → 游戏 | ❌ 无链接 |
| 歌曲 → 标签 | ❌ 标签 chips 全死（TrackDetail 显示但不可点） |
| 专辑 → 游戏/标签 | ❌ 无链接 |
| 游戏 → 专辑 | ✅（但跳的是专辑详情，非"该游戏专辑筛选"） |
| 游戏 → 游戏歌曲直览 | ❌ 无 |
| 游戏 → 其他游戏 | ❌ 无 |
| 任何页 → 标签 | ❌ 仅从 /tags 列表进入，详情页标签不可点 |

**跳转病灶**：歌曲作为内容核心，只能向上跳专辑、向下钻 credits 艺术家；向右（游戏/标签）完全断链。标签是"死胡同入口"——能进不能出。

## 5. 系统性问题 + 优先级

**P0（高优，影响基本可用）**
1. 移动端 `MobileTabBar` 补齐 `/tags`、`/me` 入口（手机用户到不了标签与个人中心）。
2. 删除死代码 `SideNav.tsx`（避免导航歧义）。
3. 统一术语：「艺术家」替代「创作者」（PageHeader/MobileTabBar 文案）。
4. 修 `AlbumDetail` 的 `MoreOutlined` 死控件（补菜单或移除）。
5. 修 `AdminLayout` 退出路由 `/admin/login`→`/` 或 `openLogin()`。

**P1（中优，IA 合理性）**
6. 补 `/games` 列表页 + 游戏详情 Hero + 游戏歌曲直览（消除最大短板）。
7. 补 `/tracks` 列表入口，让 `/track/:id` 不再孤儿（或明确歌曲永远作为专辑子项）。
8. 歌曲详情：标签 chips 可点跳 `/tags/:id`；补游戏链接。
9. 未登录态：收藏/歌单按钮置灰+登录引导，而非消失。

**P2（低优，打磨）**
10. 首页信息架构收敛（5 区块→单一核心）。
11. 汉化 `GameDetail`/`Maintenance` 英文 fallback。
12. 歌词/规格卡对普通用户折叠。
13. 后台大文件拆分。
